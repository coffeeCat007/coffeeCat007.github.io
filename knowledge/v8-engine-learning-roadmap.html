背景

学习 V8 这类底层技术时，容易出现两个问题：

一种是从编译原理、操作系统、ECMAScript 规范一路学起，基础很扎实，但路线太长，短期很难获得反馈。

另一种是直接看性能优化文章，记住了很多结论，但不知道结论背后的原因，也很难迁移到真实项目。

更合适的方式是：先建立 V8 的整体地图，再围绕真实问题逐步深入。

V8 是什么

V8 是 Google 开源的 JavaScript 和 WebAssembly 引擎，用在 Chrome、Node.js 等环境中。

它主要负责：

  • 解析 JavaScript 源码。
  • 执行 JavaScript。
  • 对热点代码做 JIT 编译优化。
  • 管理 JavaScript 对象的内存。
  • 执行垃圾回收。

需要注意的是，V8 不负责 DOM、CSS、网络请求、页面渲染这些浏览器能力。浏览器提供 Web API，V8 负责执行 JavaScript 语言本身。

V8 执行 JavaScript 的大流程

可以先用这张简化图理解：

JavaScript 源码
 -> Parser 解析
 -> AST
 -> Ignition 生成并执行字节码
 -> 收集运行时反馈
 -> Sparkplug / Maglev / TurboFan 分层编译优化
 -> 机器码执行
 -> 如果优化假设失效，deopt 回退
 -> GC 回收不用的对象

先记住几个关键词：

概念人话解释
Parser把 JavaScript 字符串读懂，变成语法结构
AST抽象语法树，表示代码结构
IgnitionV8 的解释器，先让代码快速跑起来
Sparkplug基线编译器，比解释器快，编译成本较低
Maglev中间层优化编译器，介于 Sparkplug 和 TurboFan 之间
TurboFan高级优化编译器，给热点代码生成更快机器码
Hidden Class / MapV8 给 JavaScript 对象建立的内部形状
Inline Cache缓存属性访问路径，让重复访问更快
Deopt优化假设失效，退回较低层执行
GC垃圾回收，清理不再使用的对象

第 3 阶段：理解性能核心

目标：知道为什么某些 JavaScript 写法更容易被优化。

要理解：

Hidden Class / Map
Inline Cache
对象属性添加顺序
数组 elements kinds
快属性 / 慢属性
deopt

可以先做这个小实验：

const a = { x: 1, y: 2 };
const b = { x: 3, y: 4 };

const c = {};
c.x = 1;
c.y = 2;

const d = {};
d.y = 2;
d.x = 1;

观察重点：

  • a 和 b 更可能拥有相同对象形状。
  • c 和 d 因为属性添加顺序不同，可能形成不同对象形状。
  • 对象形状稳定时，属性访问更容易被 V8 优化。

学习方式建议

建议采用这个比例：

70% 小实验
20% 官方文档
10% 总结复盘

每次只抓一个问题：

为什么对象属性顺序会影响性能？
为什么数组混入不同类型会变慢？
为什么热点函数会被优化？
为什么优化后的代码还会退回去？
为什么频繁创建对象会触发 GC 压力？

然后按这个循环推进：

真实问题 -> 最小理论 -> 小实验 -> 解释现象 -> 补理论 -> 再实验

判断是否学会

不是能背出 V8 名词就算学会，而是能做到三件事：

  1. 用人话解释一个 V8 概念。
  2. 用代码实验证明一个性能现象。
  3. 在真实项目里判断问题可能来自对象形状、数组类型、JIT、deopt 还是 GC。

最短结论

学习 V8 的目标不是把源码从头读到尾，而是建立一张能指导实践的地图。

先知道 V8 如何执行 JavaScript，再理解哪些代码形态容易被优化，最后用 DevTools、d8 和真实代码验证自己的理解。

这样学习，理论不会悬空，实践也不会变成乱试。
